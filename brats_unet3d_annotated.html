BraTS 2025 GLI — 3D U-Net Tumor Segmentation¶

Author: Ganji Revanth Kumar Data: BraTS 2025 GLI pre-operative challenge training set, 1251 cases Environment: Kaggle, single GPU, TensorFlow / Keras 3

What this notebook does¶

Multi-modal brain MRI (four sequences per patient) goes in, a voxel-wise tumor label map comes out. The pipeline is:

NIfTI volumes (182x218x182, 4 modalities)
    -> per-modality z-score over brain voxels only
    -> resample to 48x48x48
    -> cache as .npy
    -> tf.data pipeline
    -> 3D U-Net (3 levels, skip connections, soft Dice loss)
    -> voxel-wise class probabilities

Why this sits on an engineering CV¶

The physics is unrelated, but the object is not: this is 3D deep learning on a gridded volumetric field with multiple input channels. Swap MRI intensities for a voxelised stress or velocity field and the machinery is the same. That was the reason I built it.

A note on the reported metrics¶

Sections 9 and 10 matter most if you are reviewing this critically. The Dice and IoU numbers produced in Section 9 are inflated, and Section 10 explains why and gives the corrected evaluation. I found the problem after the fact. The original code and its outputs are left in place rather than quietly replaced, because the failure mode is a common and instructive one.

1. Dataset layout¶

Each case is a directory containing five NIfTI files: four MRI modalities and one expert-annotated segmentation mask.

  • t1n — T1-weighted, native
  • t1c — T1-weighted, post-contrast (enhancing tumor shows up here)
  • t2w — T2-weighted
  • t2f — T2-FLAIR (edema shows up here)
  • seg — ground truth label map

Different tumor tissues are visible in different sequences, which is why all four are fed to the network as channels rather than picking one.

3. Preprocessing and caching¶

Two decisions worth explaining:

Z-score per modality, over brain voxels only. MRI intensities have no absolute units — the same tissue gives different numbers on different scanners, so each volume has to be standardised against itself. The brain mask (> 0) matters because roughly 80% of each volume is air. Including it would drag the mean toward zero and shrink the standard deviation, compressing all the tissue contrast the network needs.

Nearest-neighbour resampling for the mask (order=0), trilinear for the image (order=1). Interpolating a label map would invent fractional label values that correspond to no tissue at all.

Downsampling to 48³ is the biggest compromise in this notebook. It is roughly a 4x reduction per axis from the native 182³, done to fit training in a Kaggle session. Small structures — thin enhancing rims especially — get partially averaged away. Any metric reported here is therefore not comparable to BraTS leaderboard numbers, which are computed at full resolution.

Preprocessing runs once and writes .npy files, so training epochs are not paying the NIfTI decode and resample cost repeatedly.

def preprocess_and_save_case(case_dir, target_shape, save_dir):
    os.makedirs(save_dir, exist_ok=True)
    modalities = ['t1n', 't1c', 't2w', 't2f']
    images = []
    files = os.listdir(case_dir)
    for mod in modalities:
        file_name = [f for f in files if f.endswith(f'-{mod}.nii')][0]
        img = nib.load(os.path.join(case_dir, file_name)).get_fdata()
        images.append(img)
    image = np.stack(images, axis=-1)
    mask_file = [f for f in files if f.endswith('-seg.nii')][0]
    mask = nib.load(os.path.join(case_dir, mask_file)).get_fdata()
    mask_remapped = mask.copy()
    mask_remapped[mask == 2] = 1
    mask_remapped[mask == 3] = 2

    # Z-score normalization (per modality, only brain)
    image_norm = image.copy()
    for i in range(image.shape[-1]):
        modality = image[..., i]
        brain_mask = modality > 0
        mean = modality[brain_mask].mean() if np.any(brain_mask) else 0
        std = modality[brain_mask].std() if np.any(brain_mask) else 1
        image_norm[..., i][brain_mask] = (modality[brain_mask] - mean) / (std + 1e-8)

    # Resize to target shape
    factors = [t / s for t, s in zip(target_shape, image_norm.shape[:3])]
    resized_image = np.zeros(target_shape + (image_norm.shape[3],), dtype=np.float32)
    for i in range(image_norm.shape[3]):
        resized_image[..., i] = zoom(image_norm[..., i], factors, order=1)
    resized_mask = zoom(mask_remapped, factors, order=0).astype(np.uint8)

    np.save(os.path.join(save_dir, 'input.npy'), resized_image)
    np.save(os.path.join(save_dir, 'label.npy'), resized_mask)
    return os.path.join(save_dir, 'input.npy'), os.path.join(save_dir, 'label.npy')

4. Input pipeline¶

tf.data reads the cached arrays, one-hot encodes the labels, batches, and prefetches so that data loading overlaps with GPU compute.

tf.py_function is used because np.load is not a TensorFlow op. This is the pragmatic choice, not the fast one — it holds the Python GIL, so it caps parallelism. A TFRecord pipeline would be faster and is the obvious next step for a larger run.

Batch size is 2, which is what a 48³×4 volume plus a 3-channel output allows on a single Kaggle GPU.

    X = np.load(input_path.numpy().decode('utf-8')).astype(np.float32)

5. Model and loss¶

Architecture¶

A 3-level 3D U-Net. The encoder halves spatial resolution three times while doubling channel width (32 → 64 → 128 → 256 at the bottleneck), and the decoder mirrors it with transposed convolutions.

Skip connections are the whole point of a U-Net. Pooling gives the network enough receptive field to know what it is looking at, but destroys the precise voxel boundaries. The skip connections carry high-resolution spatial detail from each encoder level directly across to the matching decoder level, so the output can be both semantically correct and spatially sharp. Without them the segmentation comes out as blurred blobs.

he_normal initialisation pairs with ReLU. Batch norm after each convolution keeps activations well-scaled through a fairly deep stack. Dropout 0.3 at each level, which is aggressive but the training set is small relative to the parameter count.

Soft Dice loss¶

Class imbalance here is extreme: tumour is a small fraction of the volume, and enhancing tumour smaller still. Cross-entropy on this data lets the network reach very high accuracy by predicting "background" almost everywhere. The training log in Section 7 shows exactly that — 99.7% accuracy, which is meaningless.

Dice is a set-overlap measure, so it is insensitive to how much background there is. Making it differentiable means using the predicted probabilities directly instead of thresholding, hence "soft". The smooth term prevents division by zero when a class is absent from a batch — and in Section 10 that same term turns out to be what inflated the reported score.

def conv3d_block(input_tensor, n_filters, kernel_size=3, batchnorm=True):
    x = layers.Conv3D(filters=n_filters, kernel_size=kernel_size,
                      kernel_initializer='he_normal', padding='same')(input_tensor)
    if batchnorm:
        x = layers.BatchNormalization()(x)
    x = layers.Activation('relu')(x)
    x = layers.Conv3D(filters=n_filters, kernel_size=kernel_size,
                      kernel_initializer='he_normal', padding='same')(x)
    if batchnorm:
        x = layers.BatchNormalization()(x)
    x = layers.Activation('relu')(x)
    return x

def build_3d_unet(input_shape=(48,48,48,4), n_filters=32, n_classes=3, dropout=0.3):
    inputs = layers.Input(input_shape)
    c1 = conv3d_block(inputs, n_filters)
    p1 = layers.MaxPooling3D((2, 2, 2))(c1)
    p1 = layers.Dropout(dropout)(p1)
    c2 = conv3d_block(p1, n_filters*2)
    p2 = layers.MaxPooling3D((2, 2, 2))(c2)
    p2 = layers.Dropout(dropout)(p2)
    c3 = conv3d_block(p2, n_filters*4)
    p3 = layers.MaxPooling3D((2, 2, 2))(c3)
    p3 = layers.Dropout(dropout)(p3)
    c4 = conv3d_block(p3, n_filters*8)
    u5 = layers.Conv3DTranspose(n_filters*4, (2,2,2), strides=(2,2,2), padding='same')(c4)
    u5 = layers.concatenate([u5, c3])
    u5 = layers.Dropout(dropout)(u5)
    c5 = conv3d_block(u5, n_filters*4)
    u6 = layers.Conv3DTranspose(n_filters*2, (2,2,2), strides=(2,2,2), padding='same')(c5)
    u6 = layers.concatenate([u6, c2])
    u6 = layers.Dropout(dropout)(u6)
    c6 = conv3d_block(u6, n_filters*2)
    u7 = layers.Conv3DTranspose(n_filters, (2,2,2), strides=(2,2,2), padding='same')(c6)
    u7 = layers.concatenate([u7, c1])
    u7 = layers.Dropout(dropout)(u7)
    c7 = conv3d_block(u7, n_filters)
    outputs = layers.Conv3D(n_classes, (1,1,1), activation='softmax')(c7)
    model = Model(inputs=[inputs], outputs=[outputs])
    return model

def dice_loss(y_true, y_pred, smooth=1e-6):
    axes = tuple(range(1, len(y_true.shape)-1))
    intersection = tf.reduce_sum(y_true * y_pred, axis=axes)
    union = tf.reduce_sum(y_true + y_pred, axis=axes)
    dice = (2. * intersection + smooth) / (union + smooth)
    return 1 - tf.reduce_mean(dice)

Callbacks¶

ModelCheckpoint on val_loss keeps the best model rather than the last. EarlyStopping with restore_best_weights guards against late overfitting. ReduceLROnPlateau halves the learning rate when validation stalls.

The custom periodic-save callback exists for a practical reason: Kaggle sessions have a wall-clock limit, so training had to survive being interrupted and resumed.

Resuming¶

Training ran across several Kaggle sessions, reloading the last periodic checkpoint and continuing with initial_epoch. The original notebook has one load/fit pair per session; the intermediate ones are omitted here and the final stretch is shown below.

Training in one uninterrupted run, or persisting callback state across resumes, would have saved about half the compute.

8. Evaluation as originally run — and why the numbers are wrong¶

This is the section to read carefully.

The evaluation below merges every tumour class into one binary mask (mask > 0) and then computes Dice per 2D slice, averaging over all slices of all validation volumes.

The output of the next cell shows the problem in miniature.

import numpy as np

def dice_score(y_true, y_pred, smooth=1e-6):
    y_true_f = y_true.flatten()
    y_pred_f = y_pred.flatten()
    intersection = np.sum(y_true_f * y_pred_f)
    return (2. * intersection + smooth) / (np.sum(y_true_f) + np.sum(y_pred_f) + smooth)

def iou_score(y_true, y_pred, smooth=1e-6):
    y_true_f = y_true.flatten()
    y_pred_f = y_pred.flatten()
    intersection = np.sum(y_true_f * y_pred_f)
    union = np.sum(y_true_f) + np.sum(y_pred_f) - intersection
    return (intersection + smooth) / (union + smooth)

[1.0, 0.9808, 1.0]¶

Two of those three slices scored exactly 1.0. They contain no tumour — in either the ground truth or the prediction. For an empty slice the Dice expression becomes

(2 * 0 + 1e-6) / (0 + 0 + 1e-6)  =  1.0

The smoothing term, which exists to avoid dividing by zero, hands out a perfect score for correctly predicting nothing. That is not a segmentation result.

Most axial slices of a brain contain no tumour. So when the same metric is run over the full validation set, the mean is dominated by free 1.0s.

The reported 0.936 Dice / 0.911 IoU¶

That is where the numbers on my CV came from, and there are three independent reasons not to trust them:

  1. Empty slices score 1.0. Every tumour-free slice contributes a perfect score via the smoothing term. This is the dominant effect.
  2. It is whole-tumour, not sub-region. binary_mask collapses all classes into one blob. Whole-tumour Dice is always substantially higher than per-class Dice, and enhancing tumour is the hard class.
  3. It is 2D per-slice, on 48³ volumes. BraTS reports volumetric Dice at full resolution. Neither the dimensionality nor the resolution matches.

Add the label-merging bug from Section 2 and the number describes something other than what it claims to.

9. Corrected evaluation¶

Four changes:

  • Volumetric, not per-slice. Dice is computed over the whole 3D mask.
  • Per class, not merged. Each class is scored separately, so a weak class cannot hide behind a strong one.
  • Absent-in-both returns NaN and is excluded, rather than scoring 1.0. The count of scored cases is reported alongside each mean so the reader can see how much data each number rests on.
  • No smoothing constant in the reported metric. Smoothing belongs in the loss, where it stabilises gradients. In a reported metric it manufactures scores.

These cells have not been re-executed — the trained weights are not in this session. They are the corrected code, not corrected results. The honest statement of this project's outcome is therefore: a 3D U-Net trained to convergence on downsampled BraTS 2025 volumes, with the quantitative evaluation still to be redone properly.

import numpy as np


def dice_and_iou(y_true_binary, y_pred_binary):
    """Volumetric Dice and IoU for one binary mask pair.

    Returns (nan, nan) when the class is absent from BOTH ground truth and
    prediction. Scoring an empty-empty case as 1.0 is what inflated the
    original numbers.
    """
    true_sum = y_true_binary.sum()
    pred_sum = y_pred_binary.sum()

    if true_sum == 0 and pred_sum == 0:
        return np.nan, np.nan

    intersection = np.logical_and(y_true_binary, y_pred_binary).sum()
    union = true_sum + pred_sum - intersection

    dice = 2.0 * intersection / (true_sum + pred_sum)
    iou = intersection / union if union > 0 else np.nan
    return dice, iou

CLASS_NAMES = ("background", "class_1", "class_2")


def evaluate(model, dataset, n_classes=3, class_names=CLASS_NAMES):
    """Per-class volumetric Dice and IoU across a dataset."""
    scores = {c: {"dice": [], "iou": []} for c in range(n_classes)}

    for x_batch, y_batch in dataset:
        y_pred_batch = model.predict(x_batch, verbose=0)

        for i in range(x_batch.shape[0]):
            y_true = np.argmax(y_batch[i].numpy(), axis=-1)
            y_pred = np.argmax(y_pred_batch[i], axis=-1)

            for c in range(n_classes):
                dice, iou = dice_and_iou(y_true == c, y_pred == c)
                if not np.isnan(dice):
                    scores[c]["dice"].append(dice)
                    scores[c]["iou"].append(iou)

    print(f"{'class':<16}{'n cases':>9}{'Dice':>9}{'IoU':>9}")
    print("-" * 43)

    results = {}
    for c in range(n_classes):
        dices = scores[c]["dice"]
        ious = [v for v in scores[c]["iou"] if not np.isnan(v)]
        if not dices:
            print(f"{class_names[c]:<16}{0:>9}{'absent':>9}{'absent':>9}")
            continue
        results[class_names[c]] = {
            "dice": float(np.mean(dices)),
            "iou": float(np.mean(ious)),
            "n": len(dices),
        }
        print(f"{class_names[c]:<16}{len(dices):>9}"
              f"{np.mean(dices):>9.4f}{np.mean(ious):>9.4f}")

    foreground = [v["dice"] for k, v in results.items() if k != "background"]
    if foreground:
        print("-" * 43)
        print(f"{'mean foreground':<16}{'':>9}{np.mean(foreground):>9.4f}")

    return results

10. What I would change¶

Ordered by how much each would actually matter.

1. Fix the label remap. Two tissue classes are currently merged. Train on all four BraTS labels, or merge deliberately into the standard whole-tumour / tumour-core / enhancing-tumour regions that the challenge actually scores.

2. Re-run the corrected evaluation and report per-class volumetric Dice. Enhancing tumour separately, because it is the class that discriminates between methods.

3. Train at higher resolution using patches rather than downsampling whole volumes to 48³. Patch-based training keeps native resolution at the cost of losing global context, which is the standard trade in this problem.

4. Weight the loss by class, or use Dice plus focal loss. Small classes are still under-served even with Dice.

5. Persist callback state across session resumes. Would have cut training compute roughly in half, per the plateau in Section 6.

6. Replace the tf.py_function loader with TFRecords. The current pipeline is GIL-bound.

7. Report uncertainty. A single Dice number per class says nothing about variance across cases. Per-case distributions, or at minimum an interquartile range, would be more informative — and for anything decision-critical, a calibrated confidence estimate matters more than the mean.
